# 인바운드·아웃바운드 규칙 이해

**보안 그룹(Security Group)은 EC2로 들어오거나 나가는 통신을 제어하는 가상 방화벽**이다. 인바운드와 아웃바운드는 **규칙을 적용한 EC2를 기준**으로 구분한다.

## 1. 인바운드와 아웃바운드의 차이

| 구분 | 인바운드(Inbound) | 아웃바운드(Outbound) |
|---|---|---|
| 방향 | 다른 곳 → EC2 | EC2 → 다른 곳 |
| 제어 목적 | 어디에서 오는 접속을 허용할 것인가 | 어디로 나가는 접속을 허용할 것인가 |
| 주소 항목 | 출발지(Source) | 목적지(Destination) |
| 실습 예시 | 내 컴퓨터의 SSH 접속, 사용자의 웹 접속 | 패키지·Docker 이미지 다운로드 |

인터넷뿐 아니라 같은 VPC 안의 서버 간 통신에도 적용된다. 웹 서버가 DB에 접속한다면 웹 서버에서는 아웃바운드, DB 서버에서는 인바운드다.

## 2. 실습의 보안 그룹 규칙

HTTPS 적용 후의 최종 보안 그룹 `codyssey-sg` 설정이다.

| 방향 | 프로토콜·포트 | 출발지 또는 목적지 | 의미 |
|---|---|---|---|
| 인바운드 | TCP 22 (SSH) | 출발지: 본인 공인 IP `/32` | 지정한 IP에서 서버 관리 접속 허용 |
| 인바운드 | TCP 80 (HTTP) | 출발지: `0.0.0.0/0` | 모든 IPv4 출발지의 HTTP 접속 허용 |
| 인바운드 | TCP 443 (HTTPS) | 출발지: `0.0.0.0/0` | 모든 IPv4 출발지의 HTTPS 접속 허용 |
| 아웃바운드 | 모든 트래픽 | 목적지: `0.0.0.0/0` | 모든 IPv4 목적지로 나가는 통신 허용 |

`/32`는 IPv4 주소 하나, `0.0.0.0/0`은 모든 IPv4 주소를 뜻한다. TCP 규칙의 포트는 **접속하려는 쪽의 목적지 포트**다. 예를 들어 인바운드 80은 EC2의 80번 포트, 아웃바운드 443은 접속할 상대 서버의 443번 포트를 의미한다.

보안 그룹에는 허용 규칙을 작성한다. 같은 EC2에 여러 보안 그룹을 적용하면 그 규칙들을 합쳐 허용 여부를 판단한다.

## 3. 요청에 대한 응답은 어떻게 처리하는가

보안 그룹은 **연결 상태를 추적하는 방식(Stateful)**이다. 허용된 연결의 응답은 반대 방향 규칙을 별도로 추가하지 않아도 허용된다.

| 먼저 시작한 연결 | 응답 처리 |
|---|---|
| 사용자가 EC2의 80번 포트로 접속 | EC2가 보내는 응답은 아웃바운드 규칙과 관계없이 허용 |
| EC2가 외부 서버의 443번 포트로 접속 | 돌아오는 응답은 인바운드 규칙과 관계없이 허용 |

따라서 실습의 **아웃바운드 전체 허용은 EC2가 패키지 다운로드 같은 외부 연결을 시작할 수 있도록 하는 설정**이다. 웹 요청에 응답하기 위해 모든 아웃바운드 포트를 열어야 하는 것은 아니다.

실제 통신에는 라우팅 경로와 Network ACL 등 다른 네트워크 설정도 맞아야 한다. 구성 과정은 [기본 구축 흐름](basic-build-flow.md), 최종 규칙은 [EC2 보안 설정 화면](../02_접속_검증/validation.md)을 참고한다.
