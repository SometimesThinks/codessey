# SSH 키페어의 역할과 생성 이유

**키페어(Key Pair)는 서로 대응하는 공개 키와 개인 키의 쌍**이다. 이번 Ubuntu EC2 실습에서는 SSH 접속자가 올바른 개인 키를 가지고 있는지 확인하는 인증 수단으로 사용한다.

## 1. 공개 키와 개인 키의 역할

| 구분 | 보관 위치 | 역할 |
|---|---|---|
| 공개 키(Public Key) | AWS에 등록하고, EC2 생성 시 해당 Linux 사용자의 `~/.ssh/authorized_keys`에 배치 | 접속자가 개인 키로 만든 서명을 검증 |
| 개인 키(Private Key) | 내 컴퓨터의 `.pem` 파일 | 접속할 때 자신이 해당 키의 소유자임을 증명 |

인증은 **내 컴퓨터가 개인 키로 서명하고, EC2가 공개 키로 검증하는 순서**로 이루어진다.

```text
내 컴퓨터: 개인 키로 서명 생성
                 ↓
EC2 서버: authorized_keys에 등록된 공개 키로 서명 검증
                 ↓
올바른 개인 키를 가진 사용자임을 확인하고 로그인 허용
```

공개 키는 AWS에 등록되고 EC2에도 배치된다. **개인 키는 내 컴퓨터에 보관하며 서버로 보내지 않는다.**

## 2. EC2 생성 전에 키페어를 준비하는 이유

EC2에 등록할 공개 키와, 내가 접속에 사용할 개인 키를 미리 준비하기 위해서다. EC2 생성 시 키페어를 선택하면 해당 공개 키가 서버에 배치되어 이후 SSH 인증에 사용된다.

실습에서는 다음 순서로 준비했다.

1. 키페어 이름을 `codyssey-key`, 유형을 `RSA`, 개인 키 파일 형식을 `.pem`으로 선택한다.
2. 내려받은 개인 키 파일을 내 컴퓨터에 보관한다.
3. EC2 생성 화면에서 `codyssey-key`를 선택한다.
4. SSH 접속 시 해당 개인 키를 지정해 `ubuntu` 사용자로 로그인한다.

키페어는 이번 실습의 SSH 접속 방식에 필요한 인증 수단이다. 생성 자체가 보안 그룹의 22번 포트를 열거나 EC2를 만드는 것은 아니다.

## 3. SSH 명령에서 사용하는 방법

개인 키 파일이 있는 폴더에서 실행하는 예시다. `EC2_PUBLIC_IP`는 접속할 EC2의 실제 퍼블릭 IP로 바꾼다.

```bash
chmod 400 codyssey-key.pem
ssh -i codyssey-key.pem ubuntu@EC2_PUBLIC_IP
```

| 명령 요소 | 의미 |
|---|---|
| `chmod 400` | 개인 키 파일을 소유자만 읽을 수 있도록 권한 설정 |
| `-i codyssey-key.pem` | SSH 인증에 사용할 개인 키 지정 |
| `ubuntu` | EC2 내부의 Linux 로그인 사용자 이름 |
| `EC2_PUBLIC_IP` | SSH 연결 대상 EC2의 주소 |

실습처럼 인터넷에서 직접 SSH로 접속하려면 퍼블릭 IP와 인터넷 경로, 본인 IP의 TCP 22 접속을 허용하는 보안 그룹 규칙도 필요하다. 키페어는 그 연결에서 **로그인 인증**을 담당한다.

AWS는 개인 키 사본을 보관하지 않으므로 같은 개인 키를 다시 내려받을 수 없다. 내려받은 `.pem` 파일은 외부에 공유하지 않고 보관한다.

생성·접속 과정은 [기본 구축 흐름](basic-build-flow.md), 접속 허용 설정은 [인바운드·아웃바운드 규칙](security-group-rules-explained.md)을 참고한다.
