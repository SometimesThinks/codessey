# IAM 개념과 실습 정책 JSON 이해

**IAM(Identity and Access Management)은 AWS에서 누가 어떤 리소스에 어떤 작업을 할 수 있는지 관리하는 서비스**다. 사용자의 신원을 확인하는 인증과, 작업 권한을 판단하는 인가를 담당한다.

## 1. IAM의 구성 요소

| 구성 요소 | 의미 |
|---|---|
| 사용자(User) | AWS 계정 안에서 사람이나 프로그램을 식별하는 개별 신원 |
| 그룹(Group) | 여러 IAM 사용자에게 같은 권한을 부여하기 위한 묶음 |
| 역할(Role) | 사용자나 AWS 서비스가 임시 자격 증명으로 맡아 사용하는 권한 역할 |
| 정책(Policy) | 허용·거부할 작업과 대상, 조건을 적은 권한 규칙 |

실습에서는 IAM 사용자 **`codyssey-yun`**에 정책 **`codyssey-aws-iam`**을 연결했다. 아래 설명은 [최종 정책 JSON](../../configs/iam-policy.json)을 기준으로 한다. 별도로 연결된 `IAMUserChangePassword`는 본인 비밀번호 변경을 위한 정책이다.

## 2. 실습 정책의 의미

> 요청 리전이 서울일 때, Action에 나열된 EC2·VPC 관련 작업을 허용한다. 대상 리소스를 특정 ID나 프로젝트 태그로 한정하지 않는다.

JSON은 규칙을 구조화해서 적는 형식이다. 이 파일은 **작업 권한을 정의**하며, 정책을 연결한다고 EC2나 VPC가 자동으로 생성되지는 않는다.

| JSON 항목 | 실습 값 | 의미 |
|---|---|---|
| `Version` | `2012-10-17` | IAM 정책 문법 버전. 작성 날짜와 별개 |
| `Statement` | 규칙 1개가 담긴 배열 | 실제 권한 규칙 목록 |
| `Sid` | `Ec2VpcLabInSeoul` | 규칙을 구분하는 이름. 콘솔의 정책 이름과 별개 |
| `Effect` | `Allow` | 아래 작업·대상·조건이 일치하면 허용 |
| `Action` | `ec2:Describe*` 등 37개 항목 | 허용할 AWS 작업 목록 |
| `Resource` | `*` | 대상 리소스를 특정 ID로 한정하지 않음 |
| `Condition` | `StringEquals` 조건 | 지정한 문자열과 정확히 일치하는지 확인 |
| `aws:RequestedRegion` | `ap-northeast-2` | 요청하는 AWS 서비스 엔드포인트의 리전이 서울일 때 적용 |

현재 `Statement` 안의 모든 Action에 같은 Resource와 Condition이 적용된다. 리전 조건은 사용자가 접속하는 물리적 위치나 IP 주소를 뜻하지 않는다.

## 3. Action 목록 읽기

`ec2:CreateVpc`에서 `ec2`는 서비스 접두어, `CreateVpc`는 VPC 생성 작업이다. VPC·서브넷·보안 그룹 작업도 EC2 API에 포함되어 `ec2:`로 시작한다.

| 작업 묶음 | 이 정책에서 허용하는 내용 |
|---|---|
| 조회 | `Describe*`로 EC2 관련 정보 조회, `GetSecurityGroupsForVpc`로 VPC의 보안 그룹 조회 |
| VPC·서브넷 | 생성, 속성 변경, 삭제 |
| 인터넷 게이트웨이 | 생성, VPC 연결·분리, 삭제 |
| 라우팅 테이블·경로 | 테이블 생성·삭제, 서브넷 연결·해제, 경로 추가·변경·삭제 |
| 보안 그룹 | 생성·삭제, 인바운드·아웃바운드 허용 규칙 추가·제거·수정 |
| SSH 키페어 | 생성, AWS에 등록된 키페어 삭제 |
| EC2 인스턴스 | 생성·시작·중지·재부팅·종료, 속성 변경 |
| EBS·태그 | EBS 볼륨 삭제, 리소스 태그 생성·삭제 |

`Describe*`의 `*`는 이름이 `Describe`로 시작하는 여러 조회 작업을 포함한다. 따라서 **37개는 목록의 항목 수**이며, 실제 허용 API 수와는 다르다. `RunInstances`는 새 인스턴스 생성, `StartInstances`는 중지된 인스턴스 시작이다.

## 4. 허용 범위와 제한

아래는 **이 JSON이 해당 요청에 허용 근거를 제공하는지**에 대한 예시다.

| 요청 | 이 정책의 판단 |
|---|---|
| 서울 리전에서 VPC 생성 | `CreateVpc`와 리전 조건에 해당하여 허용 |
| 도쿄 리전에서 VPC 생성 | 리전 조건이 맞지 않아 이 정책으로는 허용하지 않음 |
| IAM 사용자 생성·S3 버킷 생성 | 해당 Action이 없어 이 정책으로는 허용하지 않음 |
| 같은 계정·서울 리전의 다른 프로젝트 EC2 종료 | `TerminateInstances`가 있고 리소스별 제한이 없어 허용 범위에 포함 |

`Resource: "*"`도 **Action과 Condition의 범위 안에서 적용**된다. 이 JSON에는 인스턴스 유형·대수, EBS 용량, 보안 그룹의 포트·접속 IP를 제한하는 조건이 없다.

이 정책은 `Allow` 규칙 하나이며, 목록에 없는 작업을 명시적으로 `Deny`하지는 않는다. 다른 정책에서 추가 권한을 줄 수 있고, 적용되는 명시적 거부나 권한 경계·조직 정책은 최종 권한을 제한할 수 있다.

### 최소 권한 원칙과의 관계

**최소 권한 원칙은 필요한 작업을 필요한 대상과 조건에 한해서만 허용하는 것**이다.

- **적용한 부분:** EC2·VPC 실습에 사용할 작업을 Action에 명시하고, 이 정책의 허용 조건을 서울 리전 요청으로 제한했다.
- **남아 있는 범위:** `Describe*`는 조회 작업을 넓게 포함하고, `Resource: "*"`는 대상 리소스를 실습 프로젝트로 한정하지 않는다.
- **보완 방향:** 실제 필요한 조회 작업을 확인해 명시하고, 리소스별 제한을 지원하는 수정·삭제 작업은 실습 리소스의 ARN(식별자)이나 지원되는 태그 조건으로 범위를 좁힐 수 있다.

설정 과정은 [기본 구축 흐름](basic-build-flow.md), 전체 Action 목록은 [정책 JSON](../../configs/iam-policy.json)을 참고한다.
