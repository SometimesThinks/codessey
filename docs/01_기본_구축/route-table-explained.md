# 라우팅 테이블과 IP 주소 범위 이해

라우팅 테이블(Route Table)은 **목적지 IP에 따라 데이터를 어디로 보낼지 정하는 길 안내표**다. VPC 라우터가 이 규칙을 참고해 데이터를 전달한다.

[기본 구축 흐름](basic-build-flow.md)의 실습 구성을 기준으로 설명한다.

네트워크 구성 관계는 [VPC·서브넷·CIDR 이해](vpc-subnet-explained.md)를 참고한다.

## 1. 구성 요소의 역할

| 구성 요소 | 역할 |
|---|---|
| VPC | EC2 같은 리소스를 배치하는 가상 네트워크 공간 |
| 서브넷 | VPC의 주소 범위를 나눈 네트워크 구간 |
| 인터넷 게이트웨이(IGW) | VPC와 인터넷 사이의 출입구 |
| 라우팅 테이블 | 목적지에 따라 트래픽을 보낼 대상을 정하는 규칙표 |
| 보안 그룹 | EC2에 허용할 통신의 IP 범위·프로토콜·포트 등을 정하는 규칙 |

즉, **라우팅 테이블은 전달 경로를 정하고, 보안 그룹은 통신 허용 여부를 정한다.**

## 2. 실습 라우팅 테이블

| 목적지(Destination) | 대상(Target) | 의미 |
|---|---|---|
| `10.0.0.0/16` | `local` | VPC 내부로 전달 |
| `0.0.0.0/0` | IGW (`codyssey-igw`의 ID) | 더 구체적인 경로가 없으면 인터넷 게이트웨이로 전달 |

`local` 경로는 기본으로 생성되며, 같은 VPC의 EC2끼리 사설 IP로 통신할 때 사용한다. 이때는 IGW를 거치지 않는다.

## 3. CIDR: IP 주소 범위 읽기

`IP 주소/숫자` 형식을 **CIDR 표기법**이라고 한다. IPv4는 32비트이며, 점으로 나눈 숫자 네 개가 각각 8비트다. `/` 뒤의 숫자는 앞에서부터 고정하는 비트 수다.

| CIDR | 고정하는 부분 | 포함하는 주소 범위 |
|---|---|---|
| `10.0.0.0/16` | 앞 16비트 → `10.0` | `10.0.0.0 ~ 10.0.255.255` |
| `10.0.1.0/24` | 앞 24비트 → `10.0.1` | `10.0.1.0 ~ 10.0.1.255` |
| `0.0.0.0/0` | 고정 없음 | 모든 IPv4 주소 (`0.0.0.0 ~ 255.255.255.255`) |

**`/` 뒤의 숫자가 클수록 주소 범위가 좁다.** 실습 서브넷 `10.0.1.0/24`는 VPC `10.0.0.0/16` 안에 포함된다.

## 4. 더 구체적인 경로가 우선

목적지가 여러 경로에 해당하면 **일치하는 경로 중 `/` 뒤의 숫자가 가장 큰 경로**를 선택한다. 콘솔의 행 순서는 우선순위가 아니다.

| 목적지 IP 예시 | 선택되는 경로 | 이유 |
|---|---|---|
| `10.0.1.5` | `10.0.0.0/16 → local` | `/16`과 `/0` 모두 일치하지만 `/16`이 더 구체적 |
| `8.8.8.8` | `0.0.0.0/0 → IGW` | `/0`만 일치 |

`0.0.0.0/0`에는 VPC 내부 주소도 포함된다. 따라서 이 실습의 기본 경로는 **“다른 더 구체적인 경로가 없으면 IGW로 보내라”**는 뜻이다.

## 5. 서브넷 연결과 EC2 통신 흐름

실습에서는 `codyssey-igw`를 `codyssey-vpc`에 연결하고, 위 두 경로가 있는 `codyssey-route-table`을 `codyssey-pulic-subnet`에 연결했다.

서브넷은 한 번에 하나의 라우팅 테이블을 사용한다. 명시적으로 연결하지 않으면 VPC의 기본(Main) 테이블을 사용하며, 하나의 테이블을 여러 서브넷에 연결할 수 있다.

```text
EC2 → VPC 라우터(목적지에 맞는 경로 선택) → IGW → 인터넷
외부 사용자 → EC2 퍼블릭 IPv4로 요청 → IGW → VPC 내부 EC2
```

EC2가 IGW를 통해 인터넷과 직접 IPv4 통신하려면 **VPC에 연결된 IGW, 서브넷의 IGW 경로, EC2의 퍼블릭 IPv4**가 필요하다. 보안 그룹·Network ACL도 통신을 허용해야 한다. IGW는 EC2의 퍼블릭 IP와 프라이빗 IP 사이에서 주소를 변환한다.

웹 요청과 EC2 응답의 상세 과정은 [외부 요청과 응답 흐름](request-flow.md)을 참고한다.
