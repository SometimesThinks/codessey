# VPC·서브넷·CIDR 이해

**VPC는 가상 네트워크 공간, 서브넷은 그 안에서 EC2를 배치하는 네트워크 구간, CIDR은 IP 주소 범위를 나타내는 표기법**이다.

## 1. VPC란

**VPC(Virtual Private Cloud)는 AWS에서 다른 가상 네트워크와 논리적으로 분리된 네트워크 공간**이다. 사용할 IP 주소 범위와 서브넷, 외부 연결 경로 등을 구성한다.

VPC는 하나의 리전에 속하며, 해당 리전의 여러 가용 영역(AZ)에 서브넷을 둘 수 있다. 실습에서는 서울 리전에 `codyssey-vpc`를 만들고 주소 범위를 `10.0.0.0/16`으로 정했다.

## 2. 서브넷이란

**서브넷(Subnet)은 VPC의 주소 범위 안에서 정한 네트워크 구간**이다. EC2를 생성할 때 서브넷을 선택하면, EC2의 프라이빗 IP는 그 서브넷의 주소 범위에서 할당된다.

- 서브넷 하나는 하나의 가용 영역(AZ)에 속한다.
- 서브넷 주소 범위는 VPC 주소 범위 안에 있어야 하며, 같은 VPC의 다른 서브넷과 겹칠 수 없다.
- 서브넷별로 라우팅 테이블을 연결해 인터넷 등으로 향하는 경로를 정한다.

실습의 구성 관계는 다음과 같다. 가용 영역은 리전 안에서 물리적으로 분리된 인프라 구역이다.

```text
서울 리전: ap-northeast-2
└─ VPC: codyssey-vpc / 10.0.0.0/16
   └─ 서브넷: codyssey-pulic-subnet / 10.0.1.0/24
      │  가용 영역: ap-northeast-2a
      └─ EC2: codyssey-web / 프라이빗 IP 10.0.1.205
```

`10.0.1.205`는 서브넷 `10.0.1.0/24`에 포함되고, 이 서브넷은 VPC `10.0.0.0/16`에 포함된다. 이름과 주소는 실습 당시 기록을 기준으로 한다.

## 3. VPC와 서브넷의 필요성

### 3-1. VPC: 서비스 네트워크의 논리적 분리

AWS의 물리적 네트워크 인프라 위에서 **내 서비스가 사용할 네트워크를 논리적으로 분리**하기 위해 필요하다. 예를 들어 운영용 VPC와 개발용 VPC를 나누면 각각의 IP 주소 범위, 통신 경로, 보안 설정을 독립적으로 구성할 수 있다. 서로 다른 VPC 사이의 사설 통신에는 별도 연결 설정이 필요하다.

### 3-2. 서브넷: 통신 경로와 서버 배치의 구분

하나의 VPC 안에서 **서버의 역할과 가용 영역에 따라 네트워크를 나누기 위해** 사용한다.

- **통신 경로 구분:** 웹 서버용 Public Subnet에는 IGW로 향하는 직접 경로를 두고, DB용 Private Subnet에는 두지 않아 DB의 인터넷 직접 접속 경로를 없앨 수 있다.
- **서버 분산 배치:** 서로 다른 가용 영역에 서브넷을 만들면 서버를 나눠 배치해 한 가용 영역의 장애에 대비하는 구성을 만들 수 있다.

이번 실습은 웹 서버 한 대를 공개하는 구성이므로 Public Subnet 하나를 사용한다.

## 4. CIDR이란

**CIDR(Classless Inter-Domain Routing)은 `IP 주소/숫자` 형식으로 주소 범위를 표현하는 방식**이다.

IPv4 주소는 총 32비트이며, 점으로 구분한 숫자 네 개가 각각 8비트다. 각 숫자는 `0~255` 값을 가진다. `/` 뒤의 숫자는 **앞에서부터 고정하는 비트 수**다.

| CIDR | 고정하는 부분 | 포함하는 주소 범위 |
|---|---|---|
| `10.0.0.0/16` | 앞 16비트 → `10.0` | `10.0.0.0 ~ 10.0.255.255` |
| `10.0.1.0/24` | 앞 24비트 → `10.0.1` | `10.0.1.0 ~ 10.0.1.255` |
| `0.0.0.0/0` | 고정 없음 | 모든 IPv4 주소 (`0.0.0.0 ~ 255.255.255.255`) |

예를 들어 `/16`에서는 앞의 `10.0`을 고정하고 뒤의 두 숫자가 바뀐다. `/24`에서는 `10.0.1`을 고정하고 마지막 숫자만 바뀐다. **고정하는 비트가 많을수록 주소 범위는 좁아진다.**

`10.0.1.0/24`에는 주소가 256개 포함된다. 이번 실습과 같은 일반 AWS IPv4 서브넷에서는 앞의 네 주소와 마지막 주소를 예약하므로, 리소스에 할당할 수 있는 주소는 251개다.

`0.0.0.0/0`은 이번 실습에서 인터넷 기본 경로의 목적지 범위로 사용한다. VPC 내부 주소도 포함하지만, 경로를 선택할 때는 `/16`처럼 더 구체적으로 일치하는 경로가 우선한다.

## 5. Public Subnet과 Private Subnet

서브넷의 공개 여부는 **인터넷 게이트웨이(IGW)로 향하는 직접 경로가 있는지**로 구분한다.

| 구분 | 라우팅 설정 |
|---|---|
| Public Subnet | IGW로 향하는 직접 경로가 있음 |
| Private Subnet | IGW로 향하는 직접 경로가 없음 |

실습 서브넷에는 `0.0.0.0/0 → codyssey-igw` 경로가 있어 Public Subnet이다. `10.0.1.0/24` 같은 CIDR 값 자체가 공개 여부를 정하지는 않는다. EC2가 IGW를 통해 인터넷과 직접 IPv4 통신하려면 퍼블릭 IPv4와 통신을 허용하는 보안 규칙도 필요하다.

생성 과정은 [기본 구축 흐름](basic-build-flow.md), 경로 선택 방식은 [라우팅 테이블 설명](route-table-explained.md)을 참고한다.
